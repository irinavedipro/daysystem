# Roadmap разработки

Цель roadmap — двигаться маленькими устойчивыми шагами и не превращать приложение в сложную систему контроля.

## Этап 1. Зафиксировать смысловую основу

Статус: начат.

Задачи:

- создать очищенную продуктовую спецификацию;
- убрать дублирование ТЗ;
- зафиксировать MVP-границы;
- зафиксировать, что приложение строится вокруг состояния, выбора и одного действия, а не вокруг списка задач.

Критерий готовности:

- в репозитории есть `docs/product-spec.md`;
- в репозитории есть `docs/roadmap.md`.

## Этап 2. Пересобрать модель дня

Задачи:

- добавить структуру `DailyEntry`;
- хранить состояние дня отдельно от списка задач;
- добавить поля: сон, энергия, напряжение, ясность, тревожность, контакт с телом;
- добавить одно главное действие;
- добавить восстановление;
- добавить вечернюю фиксацию.

Критерий готовности:

- день можно заполнить без AI;
- данные сохраняются в `localStorage`;
- один день содержит достаточно данных для истории и недельного обзора.

## Этап 3. Экран «Сегодня»

Задачи:

- заменить фокус интерфейса со списка задач на состояние дня;
- добавить шкалы 0–10;
- добавить телесные чекбоксы;
- добавить карточку режима нервной системы;
- добавить одно главное действие;
- добавить поле восстановления;
- добавить вечернюю фиксацию.

Критерий готовности:

- утром можно собрать день за 2–3 минуты;
- интерфейс не провоцирует добавлять много задач.

## Этап 4. Локальная логика режимов

Задачи:

- добавить функцию определения режима: ресурс, мобилизация, перегруз, замирание;
- включать минимальный день при перегрузе;
- запрещать расширение плана при напряжении выше 7;
- не предлагать стратегические решения при ясности ниже 3.

Критерий готовности:

- базовая защита от перегруза работает без AI.

## Этап 5. Экран «Точка выбора»

Задачи:

- добавить отдельную вкладку;
- добавить вопрос «доказать или создать?»;
- добавить ответы: доказать, создать, смешано, избегаю, не понимаю;
- добавить вопросы про сжатие/раскрытие, контроль/допущение, избегание/присутствие;
- добавить локальную рекомендацию по уменьшению объёма.

Критерий готовности:

- перед важным действием можно быстро проверить источник решения.

## Этап 6. Перепрошить AI-навигатор

Задачи:

- заменить текущую AI-схему плана на короткий JSON-ответ;
- добавить правила месяца 2;
- добавить запрещённые формулировки;
- добавить защиту от стратегических решений в перегрузе;
- сделать AI-ответ карточкой стабилизации, а не списком задач.

Критерий готовности:

- AI возвращает `state`, `main_risk`, `decision_source`, `today_focus`, `body_support`, `what_to_remove`, `recovery`, `phrase`.

## Этап 7. История дней

Задачи:

- показывать список дней;
- показывать режим, главное действие, победу, откат и восстановление;
- отделить историю дней от истории AI-запросов;
- подготовить данные для недельного обзора.

Критерий готовности:

- можно увидеть, что реально поддерживает устойчивость.

## Этап 8. 7 дней использования

Задачи:

- использовать приложение ежедневно;
- фиксировать, какие поля полезны;
- убрать лишние поля;
- уточнить язык AI;
- собрать реальные паттерны.

Критерий готовности:

- есть 7 заполненных дней;
- понятно, что нужно перенести в базу.

## Этап 9. Backend, Timeweb DB и Yandex AI

Задачи:

- вынести AI-запросы на backend;
- не хранить API-ключи в браузере;
- подключить Timeweb DB;
- перенести `DailyEntry`, `DecisionCheck`, `Rollback`, `WeeklyReview` в базу;
- подключить Yandex AI через серверный API;
- добавить недельный обзор по реальной истории.

Критерий готовности:

- данные не теряются при смене браузера;
- AI видит динамику;
- приложение готово к ежедневному использованию на постоянной основе.
